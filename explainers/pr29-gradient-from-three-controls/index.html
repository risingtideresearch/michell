PR 29 as a tiny program

Forget the notation for a moment. The method computes resistance, keeps the final integration spacing, then makes one extra sweep to learn which controls mattered.

1. Start with two lists

# x positions stay fixed
knots = [0, 0, 0, 100, 100, 100]

# half-breadth controls may change
P = [0, 20, 0]

The first and last controls close the hull at the centerline. The middle control pulls the curve outward.

The B-spline library can be imagined as this function:

def half_breadth(x, P):
    t = x / 100

    weights = [
        (1 - t) * (1 - t),
        2 * t * (1 - t),
        t * t,
    ]

    return dot(P, weights)

At x = 50, the weights are [0.25, 0.50, 0.25]. The function returns 0×0.25 + 20×0.50 + 0×0.25 = 10. The half-breadth is 10; the full beam is 20.

2. Turn breadth into widening and narrowing

Michell cares about where the hull widens and narrows. We can write that as another weighted sum of the same controls:

def hull_slope(x, P):
    t = x / 100

    slope_weights = [
        -2 * (1 - t) / 100,
         2 * (1 - 2*t) / 100,
         2 * t / 100,
    ]

    return dot(P, slope_weights)

This function only multiplies each control by a fixed weight and adds the results. If you double a control, you double that control’s contribution. That is all “linear in the controls” means here.

Checkpoint: fixed knots determine the weights. Controls provide the values being weighted. As long as the knots stay fixed, the program’s structure stays fixed.

3. Make one toy wave measurement

Before using the real solver, pretend we have one wave sensor. It mixes the three controls using the made-up response [-1, 2, -1]:

def toy_resistance(P):
    response = [-1, 2, -1]  # invented teaching values

    amplitude = dot(P, response)
    resistance = amplitude * amplitude

    return resistance, amplitude, response


R, amplitude, response = toy_resistance([0, 20, 0])

# amplitude = 40
# R = 1600

The response values are not Michell coefficients. They simply give us a tiny program with the same shape as the real one: mix controls into a wave amplitude, then square that amplitude.

The response also sums to zero. Add the same number to all three controls and the amplitude does not change; the returned gradient always sums to zero. The real PR tests this same null direction because a uniform breadth offset has no longitudinal slope.

4. Run the toy program backward

The forward function returned amplitude and response because the backward function needs them:

def toy_backward(amplitude, response):
    # resistance = amplitude * amplitude
    resistance_change_per_amplitude = 2 * amplitude

    gradient = [0, 0, 0]

    for k in range(3):
        gradient[k] = (
            resistance_change_per_amplitude
            * response[k]
        )

    return gradient


gradient = toy_backward(40, [-1, 2, -1])

# gradient = [-80, 160, -80]

Read gradient[1] = 160 as: “Near the current hull, increasing the middle control by a tiny amount increases the toy resistance about 160 times that amount.” If the endpoint controls must stay zero, the optimizer ignores the other two entries.

The first payoff: we did not run the resistance calculation six times. One forward call saved the intermediate amplitude. One backward call produced all three answers.

5. Replace the toy sensor with the real wave fan

The real solver samples many wave directions. At each sample, every control has a different response. The numbers are complex because they carry both wave size and phase.

def real_resistance(P, fixed_knots):
    spacing = initial_spacing

    while True:
        wave_nodes = integration_nodes(spacing)
        resistance = 0

        for node in wave_nodes:
            response = control_responses(node, fixed_knots)
            amplitude = dot(P, response)   # complex number
            resistance += abs(amplitude) ** 2 * node.weight

        if converged(resistance):
            return resistance, spacing

        spacing = refine(spacing)

This repeats the toy program once per wave sample. node.weight carries the panel width, the Gauss weight within that panel, and the sec³(theta) factor from Michell’s outer integral.

A teaching version could save every amplitude and response as a tape. The real code stores no per-node tape: it keeps the final refinement spacing, makes one extra sweep over only those final nodes, and recomputes the same amplitudes and responses in constant memory.

6. Run the real program backward

def real_backward(P, final_spacing, fixed_knots):
    gradient = [0] * len(P)

    final_nodes = integration_nodes(final_spacing)

    for node in final_nodes:
        response = control_responses(node, fixed_knots)
        amplitude = dot(P, response)       # recomputed

        for k in range(len(P)):
            contribution = 2 * real_part(
                conjugate(amplitude) * response[k]
            )

            gradient[k] += contribution * node.weight

    return gradient

The unfamiliar complex-number line does the same job as 2 * amplitude * response[k] in the toy program. It accounts for wave phase. The important part is the loop: each recomputed amplitude updates every control’s gradient.

8. What finite differences would do instead

def finite_difference_gradient(P):
    gradient = [0] * len(P)

    for k in range(len(P)):
        P_plus  = copy(P)
        P_minus = copy(P)
        P_plus[k]  += tiny_step
        P_minus[k] -= tiny_step

        R_plus  = run_entire_resistance_solver(P_plus)
        R_minus = run_entire_resistance_solver(P_minus)

        gradient[k] = (R_plus - R_minus) / (2 * tiny_step)

    return gradient

PR 29 does not make its own arithmetic independent of control count; it still visits spline spans and basis functions. What it removes is the need for two complete resistance solves per control.

9. One implementation detail inside PR 29

The actual solver works with polynomial slope coefficients on each knot span. Its final bookkeeping step maps those internal gradients back to the original control net:

# The forward setup did this:
span_coefficients = control_to_span_map(P, fixed_knots)

# The resistance backward pass first returns this:
gradient_for_span_coefficients = backward_through_waves(
    P,
    final_spacing,
    fixed_knots,
)

# Now send each internal contribution back to the controls
# that produced it. This loop is the "transpose" operation.
gradient_for_controls = [0] * len(P)

for span_coefficient in all_span_coefficients:
    for control in controls_used_by(span_coefficient):
        gradient_for_controls[control] += (
            control_to_span_weight[span_coefficient][control]
            * gradient_for_span_coefficients[span_coefficient]
        )

No approximation happens in that last loop. It walks the fixed spline conversion backward.

10. Where autodiff fits

An autodiff system can plug PR 29 into a larger design program as a hand-written backward function:

def full_design_forward(q):
    P, hull_saved = make_hull_forward(q)
    R, final_spacing = resistance_forward(P)

    context = (P, hull_saved, final_spacing)
    return R, context


def full_design_backward(context):
    P, hull_saved, final_spacing = context

    # PR 29 handles this line:
    gradient_for_P = resistance_backward(P, final_spacing)

    # The geometry generator must handle this line:
    gradient_for_q = make_hull_backward(
        hull_saved,
        gradient_for_P,
    )

    return gradient_for_q

q might contain beam, camber, or other high-level design parameters. make_hull_forward(q) converts them into spline controls. PR 29 moves the gradient from resistance back to those controls. Autodiff then moves it through the geometry generator, from the controls back to q.

11. What the returned list means

gradient_for_controls = [g0, g1, g2, ...]

# g1 answers:
# "If P[1] increases slightly while everything else stays
#  fixed, how quickly does resistance change?"

A positive entry means widening at that control raises resistance locally. A negative entry means widening there lowers resistance locally. The optimizer usually steps in the opposite direction, subject to closed ends, volume, stability, and other design constraints.

One-program version: forward(P) computes resistance and keeps the final integration spacing. backward(P, spacing) revisits only those final nodes, recomputes their amplitudes, and returns one gradient value per control. Fixed knots make each control’s response reusable.
